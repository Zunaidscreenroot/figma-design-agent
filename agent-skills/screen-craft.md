# Senior-Level Screen Craft Skill

## Goal
Generate UI screens that feel purpose-built by an experienced product designer, not generic output from a conversational model.

## Before layout
- Identify user goal, expertise, task frequency, risk level and decision complexity.
- Separate primary, secondary and tertiary information.
- Identify what needs to be compared, entered, reviewed, monitored or confirmed.
- Use actual product rules and data. Flag missing decisions rather than inventing them.

## Composition
- Choose a domain-specific pattern: forms, comparison tables, data-heavy workspace, map/list, approval queue, detail view, onboarding, payment, confirmation or another evidenced pattern.
- Match content density to the workflow. Enterprise workspaces may be dense; guided consumer flows may be more spacious.
- Establish hierarchy through placement, type scale, grouping, contrast and whitespace.
- Use cards only when a group needs a distinct surface or interaction boundary.
- Keep primary action placement consistent with approved examples.
- Use real field labels, contextual helper text, statuses, summaries, data values and useful empty/error states.
- Keep repeated elements aligned to a shared grid and spacing rhythm.

## Reference and system use
- Prefer an exact component, compatible variant, known pattern, and then primitives.
- Reuse project tokens/variables when available.
- Learn patterns from accepted screens of the same task type and product area.
- Record evidence for important choices.
- If no reference or token exists, use a restrained coherent choice and expose the assumption.

## Avoid common generated-UI tells
Avoid unnecessary card nesting, repetitive equal-card layouts, oversized generic headlines on utilitarian screens, gratuitous gradients or blobs, shadow-heavy surfaces, excessive pills, inconsistent radii, placeholder copy, arbitrary data, identical layouts across unrelated products, unjustified whitespace and hidden primary actions.

## Validation and learning
Check requirements, hierarchy, readability, alignment, content density, responsiveness, structure, component/token use, placeholder copy and screenshot fit. Use accepted examples and explicit corrections as scoped evidence. Do not elevate one correction to a global rule unless repeated evidence supports it.
